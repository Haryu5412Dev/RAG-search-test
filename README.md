# RAG Search Test

Qwen3-4B 모델을 사용한 문서 기반 질의응답(RAG) 시스템

## 📁 프로젝트 구조

```
RAG-search-test/
├── main.py                    # 메인 실행 프로그램 (인터랙티브 CLI)
├── requirements.txt           # Python 패키지 의존성
├── .env                       # 환경변수 설정 (API 키 등)
├── .env.example               # 환경변수 예시 파일
│
├── data/                      # 문서 데이터
│   └── PLM_training_manual_clean.txt  # 국방표준정보 관리 시스템 매뉴얼
│
├── output/                    # 질의응답 결과 저장 폴더
│   └── 질문_yyyymmdd_hhmmss.txt
│
└── util/                      # 유틸리티 모듈
    ├── __init__.py
    ├── chunking.py            # 문서 청킹 (페이지/헤더 기반)
    ├── retrieval.py           # TF-IDF 기반 의미론적 검색
    ├── generation.py          # LLM 답변 생성 + 최적화
    ├── cache.py               # LLM 응답 캐싱 (중복 방지)
    └── rate_limit.py          # API 호출 제한
```

## 🚀 시작하기

### 1. 의존성 설치

```bash
pip install -r requirements.txt
```

### 2.**환경 변수 설정:**

- `USE_GPU=true`: GPU 사용 (CUDA 필요, 빠름 - 15-20초)
- `USE_GPU=false`: CPU만 사용 (GPU 없어도 실행 가능, 느림 - 60-120초)
- `CPU_THREADS=2`: CPU 스레드 수 제한 (기본값 2, 안정성 우선)
- `HF_HOME`: Hugging Face 모델 캐시 저장 위치

**CPU 모드 최적화:**
- CPU 모드(`USE_GPU=false`)일 때 자동으로 적용되는 최적화:
  - INT8 동적 양자화 (메모리 사용량 감소)
  - 스레드 수 제한 (기본 2스레드, 안정성 우선)
  - Context 크기 대폭 감소 (200자 → 50자)
  - Token 생성 최소화 (256 → 64)
  - 검색 청크 감소 (3개 → 2개)
  - KV 캐시 비활성화 (메모리 절약)

**성능 권장사항:**
- CPU 모드는 최소 8GB RAM 권장 (16GB 이상 권장)
- `CPU_THREADS=2`: 안정성 우선 (메모리 부족 시)
- `CPU_THREADS=4`: 성능 우선 (시스템 여유 있을 때)
- 메모리 부족 시 다른 프로그램 종료 후 실행

### 3. 실행

```bash
python main.py
```

### 4. 사용 방법

- **메뉴 선택**: 화살표 키(↑↓) 또는 숫자 키(1, 2) 사용
- **질문 입력**: 자유로운 한글 질문 입력
- **답변 확인**: LLM이 생성한 요약 답변 표시
- **결과 저장**: 자동으로 `output/` 폴더에 저장

## ✨ 주요 기능

### 🎯 핵심 기능
- **자동 문서 처리**: PLM 매뉴얼 자동 로드 및 청킹 (50개 청크)
- **의미론적 검색**: TF-IDF 기반 관련성 높은 문서 검색
- **Qwen3-4B 모델**: 최적화된 로컬 LLM으로 빠른 답변 생성
- **대화형 인터페이스**: 컬러풀한 메뉴와 향상된 사용자 경험
- **자동 저장**: 모든 질의응답을 타임스탬프 포함 파일로 저장

### ⚡ 성능 최적화

**GPU 모드:**
- **4-bit 양자화**: 모델 크기 4GB → 1GB (75% 감소)
- **Context 최적화**: 불필요한 텍스트 제거 (200자 제한)
- **Token 감소**: max_new_tokens 512
- **Greedy Decoding**: 확률 샘플링 제거 (속도 향상)
- **모델 프리로딩**: 프로그램 시작 시 모델 미리 로드
- **응답 캐싱**: 동일 질문 즉시 반환

**CPU 모드 전용 최적화:**
- **INT8 동적 양자화**: GPU 대비 메모리 효율적 (float32 → int8)
- **스레드 수 제한**: CPU 점유율 제어 (기본 2스레드, 안정성 우선)
- **Context 대폭 축소**: 각 청크 50자로 제한 (GPU: 200자)
- **청크 수 감소**: 2개만 사용 (GPU: 3개)
- **Token 최소화**: max_new_tokens 64 (GPU: 512)
- **KV 캐시 비활성화**: 메모리 사용량 최소화
- **저전력 모드**: low_cpu_mem_usage 활성화

### 🎨 사용자 경험
- **컬러 메뉴**: questionary 라이브러리로 전문적 인터페이스
- **실시간 피드백**: 로딩 스피너, 진행률 표시
- **깨끗한 터미널**: 매 단계마다 화면 청소
- **성능 측정**: 답변 생성 소요 시간 표시
- **에러 처리**: 명확한 오류 메시지와 폴백 처리

## 🛠️ 기술 스택

### 핵심 라이브러리
- **LLM**: Qwen3-4B-Instruct-2507 (Hugging Face Transformers)
- **검색 엔진**: scikit-learn (TF-IDF)
- **GPU 최적화**: PyTorch + CUDA 12.8
- **양자화**: BitsAndBytes (4-bit)

### 기타 도구
- **CLI**: questionary (인터랙티브 메뉴)
- **캐싱**: JSON 기반 응답 캐시
- **환경 설정**: python-dotenv

## ⚙️ 성능 개선 내역

### 모델 최적화
1. **4-bit 양자화 (Quantization)**
   - 메모리 효율: 4GB → 1GB
   - 추론 속도: 2-3배 향상

2. **Context 최적화**
   - 최대 200자로 제한 (불필요한 정보 제거)
   - 모델이 처리할 정보량 감소

3. **Token 생성 최적화**
   - max_new_tokens: 512 → 256
   - Greedy Decoding (확률 샘플링 제거)

4. **모델 로딩**
   - Flash Attention 2 (선택사항)
   - 프리로딩으로 초기화 후 즉시 응답

### 예상 성능
- **첫 질문**: 15-20초 (모델 로드 포함)
- **이후 질문**: 5-10초 (캐시 활용)
- **캐시된 질문**: <1초 (즉시 반환)
